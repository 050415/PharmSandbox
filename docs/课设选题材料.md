# 药盘推演（PharmSandbox）智能体——课设选题材料

---

## 一、医疗健康应用需求及智能体在其中可能发挥的作用

### 1.1 行业痛点：合理用药的"三重困境"

在当前临床实践中，多药联用（Polypharmacy）已成为慢病管理的常态。据统计，65岁以上老年患者平均同时服用5种以上药物，由此引发的药物-药物相互作用（DDI）问题构成了严峻的用药安全隐患。目前市面上的合理用药软件（临床决策支持系统，CDSS）普遍存在以下三重困境：

**困境一："死板拦截"——规则引擎的本位缺陷。** 传统CDSS采用硬编码规则库，仅执行"A药+B药=冲突"的二元判断。这种机制完全忽略了患者的个体差异——同为"阿司匹林+华法林"的组合，对于一位30岁健康人群和一位75岁肾功能不全的老年患者，其出血风险截然不同，但传统系统给出的警报完全相同。这导致了严重的"警报疲劳"（Alert Fatigue）现象：研究显示，临床医生对CDSS弹窗的忽略率高达90%以上。

**困境二："被动响应"——缺乏主动推理能力。** 现有系统只能在医生开出处方后进行事后拦截，无法主动预测未知或罕见的药物冲突。当两种药物从未在临床试验中被联合测试过时，规则库便束手无策。系统无法像一位经验丰富的临床药师那样，基于药物的分子结构、代谢通路和靶点蛋白信息进行"举一反三"的推理。

**困境三："孤岛运行"——缺乏持续性药学服务。** 慢病患者的用药管理是一个连续的生命周期过程，涉及续方、剂量调整、副作用监测等多个环节。现有系统仅在开药瞬间提供一次性的静态判断，无法提供主动式的续方提醒、随访评估和个性化健康指导。

### 1.2 智能体的破局作用：从"死板拦截"到"沙盘推演"

本项目设计的"药盘推演"（PharmSandbox）智能体，旨在从根本上突破上述三重困境。智能体的核心定位是：**一位全天候、有推理能力、懂病理的虚拟临床药师**。它在合理用药场景中发挥以下四重关键作用：

**作用一：主动式隐性DDI沙盘推演。** 区别于传统CDSS的"查表拦截"，本智能体在内部构建了一个庞大的药物知识图谱（包含药物分子结构、靶点蛋白、代谢酶CYP450家族、副作用等多维信息），并利用图神经网络（GNN）在虚拟沙盘中对药物组合进行"推演"。这使得智能体不仅能识别已知的药物冲突，更能基于分子结构和拓扑关系预测未知的、罕见的隐性DDI——正如AlphaFold预测蛋白质结构一样，智能体从药物的"底层生化底色"中发现潜在风险。

**作用二：患者特异性风险量化评分。** 智能体将传统的"能吃/不能吃"二分类判断，升级为0-100分的连续量化风险评分。它会动态调取患者的年龄、既往病史、肝肾功能化验值等个体信息，作为沙盘推演的实时环境约束。例如，当智能体获取到患者最新化验单显示"肌酐清除率极低（肾功能不全）"时，便会大幅调高具有肾毒性副作用药物的风险权重，使该药物对该特定患者的评分飙升至90分以上（极度高危）。

**作用三：因果约束下的无害化替代药物推荐。** 当风险评分判定某药物具有高危风险时，智能体不是简单地发出"禁止使用"的警报，而是进一步调用自定义推荐函数，依据ATC分类树和适应症数据，在同类药物中横向搜索既能治疗本病、又不会与现有用药产生冲突的替代品，并严格按照临床治疗指南的推荐阶梯（一线、二线用药）给出建议。

**作用四：主动式慢病续方触发与时序随访。** 智能体内置时间触发器，持续计算患者剩余药量。在药品即将耗尽的前3天，智能体会自主触发触达事件，评估患者近期的用药副作用反馈，并辅助生成结构化续方草稿推送给医生审核，实现从"被动等患者来"到"主动管患者用"的服务模式转变。

## 二、智能体参与医疗健康业务的工作方式及其与医生/病患/设备之间的数据/信息/对话方式

### 2.1 总体工作方式：三层架构驱动的"感知-决策-行动"闭环

本智能体采用经典的三层架构设计，形成完整的"感知-决策-行动"闭环：

- **感知层（Perception Layer）**：通过自然语言理解（NLU）技术，从患者对话或电子健康记录中提取药物名称、剂量、症状等关键信息，调用药物名称标准化映射表（drug_names.tsv）进行ID归一化，将模糊的用户输入转化为结构化的药物实体。
- **决策层（Decision-Making Layer）**：作为智能体的"医疗AI推理大脑"，整合图神经网络DDI推演、0-100风险量化评分、替代药物推荐算法和慢病续方触发器四大核心模块，基于药物知识图谱和患者特异性约束进行综合推理。
- **行动层（Action Layer）**：通过调用外部工具API执行任务——若判定用药安全，自动生成结构化续方草稿发送给HIS系统；若判定存在高风险，触发替代药品推荐并在前端为患者或医生输出带有数据可视化的雷达风险图。

### 2.2 智能体与病患（C端）的交互方式

**交互模式：自然语言多轮对话，主动服务。**

患者端的交互以通俗易懂的自然语言对话为核心。患者可以通过手机APP或网页端向智能体反馈以下信息：

- **主观症状上报**："我最近吃降压药后总觉得头晕"——智能体通过医学NER模块识别出药物（降压药→氨氯地平）和症状（头晕），结合SIDER副作用数据库判断该症状是否为已知副作用，并评估严重程度。
- **用药依从性反馈**："我昨天忘记吃二甲双胍了"——智能体记录用药缺口，评估漏服对血糖控制的影响，并在下次对话中主动提醒。
- **化验报告上传**：患者拍照上传化验单，智能体提取肌酐、ALT、INR等关键指标，自动更新患者风险画像。
- **通俗化用药解答**：患者询问"这两种药能一起吃吗"，智能体以通俗语言解释DDI风险，而非输出晦涩的医学术语。

智能体同时具备主动服务能力：在药品即将耗尽前3天主动推送续方提醒；在患者血糖/血压监测数据异常时主动预警；在新药上市可能更适合患者时主动推荐。

### 2.3 智能体与医生（B端）的交互方式

**交互模式：智能体前置辅助，医生终审决策，数据结构化、专业度高。**

医生端的交互以结构化数据报告和风险预警推送为核心，目标是实现医疗质控与减负：

- **高危用药风险筛查报告**：智能体自动分析患者处方中的DDI风险，将沙盘推演结果以结构化报告形式推送给医生工作站。报告包含：风险评分（0-100分）、DDI冲突详情、共同副作用列表、替代药物推荐方案及推荐依据（ATC分类匹配度、适应症重合度、副作用对比）。
- **异常指标主动推送**：当智能体通过物联网接口获取到患者最新的肝肾功能化验值出现异常时，主动向医生推送预警，附带该异常指标对当前用药方案的影响分析。
- **续方草稿辅助生成**：对于慢病患者的常规续方，智能体预生成结构化续方草稿，医生只需审核确认或微调即可，减少重复性文书工作。
- **批量随访汇总**：智能体对管辖范围内的慢病患者进行批量随访数据汇总，以仪表板形式呈现群体用药安全概览，辅助医生进行质量管控。

**核心原则：智能体始终是"辅助角色"，最终处方决策权归医生所有。**

### 2.4 智能体与医疗设备/系统的交互方式

**交互模式：纯标准化机器数据流，无自然语言，实时、自动化、高可靠。**

智能体与医疗设备和信息系统之间通过标准化接口进行数据交换：

- **电子健康记录（EHR）系统对接**：智能体通过HL7/FHIR标准接口，从医院HIS系统中调取患者的电子健康记录，包括诊断编码（ICD-10）、检验结果、用药历史等结构化数据。在本项目中，我们使用MIMIC-IV公开数据集（364,627名患者、6,364,488条诊断记录、20,292,611条处方记录）作为沙盘推演的患者约束数据源。
- **物联网（IoT）设备接入**：智能体通过物联网协议接收院内设备（如监护仪、输液泵）和居家设备（如智能血压计、连续血糖监测仪）上传的实时生理数据，作为动态风险评估的输入。例如，当连续血糖监测仪报告患者血糖持续偏低时，智能体会自动调高降糖药的风险权重。
- **检验信息系统（LIS）对接**：智能体实时接收LIS系统推送的检验危急值（如INR>4.0、肌酐清除率<30ml/min），即时触发用药风险重评估。
- **处方推送**：当智能体完成风险评估且判定安全时，自动生成结构化电子处方草稿，通过API接口推送至HIS系统的医生审核队列。

### 2.6 技术实现保障

本项目的技术实现基于以下核心组件，确保智能体在实际业务场景中的可靠运行：

| 组件 | 技术方案 | 业务作用 |
|------|----------|----------|
| 药物名称识别 | 医学NER模块（正则+规则引擎，100+中文药名映射） | 感知层：从自然语言中提取药物实体 |
| DDI推演引擎 | RGCN图神经网络（基于SumGNN架构，PyTorch Geometric实现） | 决策层：预测已知和未知药物冲突 |
| 风险量化评分 | 动态加权算法（SIDER概率底表 + MIMIC-IV患者约束） | 决策层：0-100分患者特异性风险评分 |
| 替代药推荐 | ATC分类树搜索 + 适应症匹配 + 副作用对比 | 决策层：无害化替代方案生成 |
| LLM推理解释 | 模板+规则引擎（14种DDI机制解释模板） | 行动层：自然语言风险解释 |
| Web可视化 | Streamlit仪表板 + Plotly雷达图 + PyVis知识图谱 | 行动层：直观的风险可视化展示 |
| 数据基座 | SIDER + DrugCentral + TWOSIDES + MIMIC-IV | 全局：药物知识图谱和训练数据支撑 |
